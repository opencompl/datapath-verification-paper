\section{Introduction}
Datapath circuits are a fundamental component of digital systems, responsible from moving and processing data.

Adders are used extensively in processors, for address computation, data processing, and even more complex circuits are built from adders, such as multipliers and dividers.

In \ac{asic}, carry propagation is a major contributor to delay. 
In cases where multiple summands must be added, the naïve approach chains carry-propagate adders, growing the delay linearly with the number of bits and summands.
Datapath synthesis methods address this issue by reducing multiple summands to two using carry-save arithmetic, avoiding multiple carry-propagation adders to compute the sum.
The compression tree algorithms increase the difficulty of verifying the generated circuits, as they are highly optimized and complex.

Different techniques exist to verify datapath circuits, such as \ac{sca} and SAT-based methods.
A shortcoming of these methods is that not only the verification tool itself is unverified, but also they do not scale to large and complex circuits.

We take a different approach by verifying the synthesis step itself, rather than verifying the generated circuits.
This correct-by-construction approach guarantees that the generated circuits are correct, and scales to large circuits.

We formalize the bit heap data structure and compression algorithms, and integrate them into an existing industrial synthesis tool to provide formally verified datapath circuits.


Our list of contributions is as follows:
\begin{itemize} 
  \item Formalization of bit heap data structure and efficient compression algorithms in a theorem prover
  \item Integration into an existing synthesis flow to provide formally verified datapath circuits to eliminate the SAT solver bottleneck
  \item Integration of bit heap data structure into Lean 4's formally verified bit blaster to improve the solvers capabilities
  \item Verified synthesis of existing datapath benchmark suite 
\end{itemize}

\section{Background}
In digital arithmetic, an integer or fixed-point number is represented as follows:
\[
  X = \sum_{i=0}^{n-1} 2^i \cdot x_i 
\]
where a number is represented as a sum of weighted bits, with weights being a power of 2 such as $2^i$ for the bit in the $i$-th position. 
Similarly, the multiplication operation can be represented as a sum of weighted bits as follows:
\[
  \begin{aligned}
    X \cdot Y &= \left(\sum_{i=0}^{n-1} 2^i \cdot x_i\right)\left(\sum_{j=0}^{n-1} 2^j \cdot y_j\right) \\
              &= \sum_{i=0}^{n-1} \sum_{j=0}^{n-1} 2^{i+j} \cdot x_i \cdot y_j
  \end{aligned}
\]

where the term $x_i \cdot y_j$ is the logical AND of the bits, and the weight of the resulting bit is $2^{i+j}$. 
Therefore, a multiplication can be implemented as a summation of weighted bits, where the bits are generated by logical AND of the bits of the two operands.

A bit heap is a data structure that effectively represents the summation of weighted  bits \cite{arithmetic_core_generation_bitheaps}. Bits in a bit heap are organized into columns based on their weights, and the height of each column corresponds to the number of bit values that need to be summed for that particular weight.

\subsection{Compression Algorithms}
\label{comp_algo}
In arithmetic circuits, a main contributor to delay is carry propagation. In cases where multiple summands must be added, the naive approach chains carry-propagation adders, growing the delay linearly with the number of bits and summands. For example, multiplication is usually implemented as addition of multiple summands. 

Compressor trees are built to address this issue by reducing multiple summands to two using carry-save arithmetic, 
avoiding multiple carry-propagation adders to compute the sum. 

Compression reduces the height of a bit heap to two, after which a single \ac{cpa} produces the result \cite{application_specific_arithmetic}.
The reduction is carried out by compressors, half adders ($2{:}2$), full adders ($3{:}2$), or in general any $N{:}M$ compressor with $N \ge M$.

\section{Formalization}

To enable verified synthesis, we implement, and prove correctness of bit heaps, which is a data structure
that is key to perform effective synthesis of N-ary bitvector summation \cite{application_specific_arithmetic}

Toward this, we begin by defining a symbolic bit heap in Lean 4, which is a vector of columns.
Each column contains a bit expression, which is a symbolic representation of the bit that is computed.
We implement basic operations on the bit heap, including evaluating a bit heap to a concrete value, adding and removing bits, and compressing a bit heap. 
These operations then enable us to implement and prove the correctness of the construction of the compressor trees (Theorem~\ref{thm:chain-correct}). 

We now explain the individual components of our formalization, as well as key theorems that were proven
along the way to a verified datapath synthesis flow.

\subsection{Symbolic Bit Representations}
We represent symbolic bits as \BitExpr, which is a language that represents Boolean expressions.
These are the elements that are stored in the bit heap.
A \BitExpr can be a Boolean variable, constant, or Boolean operations on \BitExpr values.
Internally, \BitExpr variables are represented by a natural number index.
In order to evaluate a \BitExpr, we need the values of all the variables in the \BitExpr.
These values are supplied by a bit environment $(\sigma : \mathbb Var \to \mathbb B)$,
which maps each bit variable to its boolean value. 
The evaluation function $\csem{\cdot} : \BitExpr \to \mathbb B$ evaluates a \BitExpr $e$ under a bit environment $\sigma$,
producing a concrete boolean value. It is defined in the usual way by reduction on the language of \BitExpr.

\[
\begin{array}{r@{\;}c@{\;}l@{\qquad}l}
\multicolumn{4}{l}{%
  b \in Var  \qquad
  \circledast \in \{\wedge,\vee,\oplus\}}\\[6pt]

\BitExpr \ni c &::=& b_n \mid 0 \mid 1 \mid \neg c \mid c \circledast c &
\end{array}
\]

\[
\begin{array}{r@{\;}c@{\;}l}
\multicolumn{3}{@{}l@{}}{%
  \sigma \;:\; Var \to \mathbb{B}
  \qquad
  \csem{\cdot} \;:\; \BitExpr \to \mathbb{B}} \\[4pt]
\csem{b} &=& \sigma(b)\\
\csem{0} &=& \mathit{false}\\
\csem{1} &=& \mathit{true}\\
\csem{\neg c} &=& \neg \csem{c}\\
\csem{c_0 \circledast c_1}
  &=& \csem{c_0} \circledast \csem{c_1}
\end{array}
\]

\subsection{Bit Heap Data Structure}
A bit heap of width $w$ is a vector of $w$ columns, where the column at index $k$ holds the bits of weight $2^k$. 
A \Col is a set of \BitExpr elements.
\[
\begin{array}{r@{\;}c@{\;}l@{\qquad}l}
\Col \ni \gamma &::=& \{c_0,\dots,c_n\} \\[2pt]
 w \in \mathbb{N}^{+},  
\Heap_w \ni h &::=& \langle  \gamma_0,\dots,\gamma_{w-1} \rangle  &
\end{array}
\]

\begin{definition}[Bit heap]
\label{def:bitheap}

Recall that a bit heap is a data structure that is used to represent a summation of weighted bits.
Bits of the same weight are organized into columns, where column $k$ has weight $2^k$.
In implementing the data structure,
we define a \Col as a set of \BitExpr elements,
and a \Heap of width $w$ as a vector of $w$ columns.
\[
  \Heap\;w \;\triangleq\; \Vect(\Col\;w)
\]
\autoref{fig:bitheap-example} illustrates this for a $3 \times 3$ unsigned multiplication.
\end{definition}

\paragraph{Evaluation of Bit Heaps}
Since a bit heap represents a summation of weighted bits,
we can evaluate the bit heap $h$ under a bit environment $\sigma$ to obtain a concrete value, written as $\csem{h}$.
This is defined by adding up all the bits across all the columns, with bits at column $k$ being evaluated by $\csem{\cdot}$ and weighted by $2^k$. Moreover, since we work with fixed-size bitvectors, all our computations happen modulo $2^w$.

\[
\begin{array}{r@{\;}c@{\;}l}
\csem{\cdot} &:& \Heap_w \to \mathbb{N} \\[4pt]
\csem{h}
  &=& \Bigl(\textstyle\sum_{k<w} 2^{k} \sum_{c \in h_k} \csem{c}\Bigr)
      \bmod 2^{w}
\end{array}
\]

\begin{table*}[t]
  \centering
  \caption{Compression steps. $\maj$ denotes the majority function
           $(i \wedge j) \vee (i \wedge l) \vee (j \wedge l)$.}
  \label{tab:steps}
  \begin{tabular}{@{}lll@{}}
  \toprule
  Step & Applicability & Effect \\
  \midrule
  $\HA(k,i,j)$
    & $i,j \in \gamma_k$, $i \neq j$, $k\le w$
    & remove $i,j$ from $\gamma_k$;\;
      add $i \oplus j$ at $\gamma_k$;\;
      add $i \wedge j$ at $\gamma_{k{+}1}$ \\[2pt]
  $\FA(k,i,j,l)$
    & $i,j,l \in \gamma_k$, pairwise distinct, $k\le w$
    & remove $i,j,l$ from $\gamma_k$;\;
      add $i \oplus j \oplus l$ at $\gamma_k$;\;
      add $\maj(i,j,l)$ at $\gamma_{k{+}1}$ \\
  \bottomrule
  \end{tabular}

For the purposes of both implementation and proofs by induction,
it is much better to define the evaluation of a bit heap using Horner's method,
since it makes proofs cleaner, as it can be defined structurally recursively on the list of columns.

$v_k = \sum_{c \in h_k} \csem{c}$ for the value of the column at
index $k$:
\begin{equation}
\begin{split}
  \Bigl( \sum_{k=0}^{w-1} &v_k \cdot x^{k} \Bigr) \bmod 2^{w}\\
    &= \Bigl( v_0 + x \bigl( v_1
      + x ( v_2 + \cdots\\
    &\qquad + x \, v_{w-1} ) \bigr) \Bigr) \bmod 2^{w}
\end{split}
\end{equation}

By setting $x = 2$, so that each column at index $k$ contributes its value $v_k$ weighted by $2^{k}$, and reducing modulo $2^{w}$, we obtain the value of the bit heap.
Horner's method is structurally recursive on the list of columns, which makes it convenient for induction in Lean.

\paragraph{Constructing Bit Heaps}

A bit heap's API involves bit insertion and removal operations,
which are used by higher-level operations such as compression to create circuits like compressor trees.

In order to support efficient insertion and deletion of bits, 
a natural choice of data structure that provides $O(1)$ inserts and deletes is a (hash)-set.
However, whilst this means we cannot add the same bit twice to a column,
this actually benefits us as we explain below

% Alternatively, we could use a multi-set like data structure, realized as either a raw list
% (which would provide $O(n)$ inserts and deletes),
% or a map from \BitExpr to its multiplicity (which has $O(\log n)$ inserts and deletes).
% These are asymptotically slower than a set, so we choose to use a set for the implementation of the bit heap.
% \sam{It seems unnecessary to justify why $O(1)$ is better - I'd ditch discussion of alternative representations.}

\paragraph{Insertion}
Inserting a bit expression $e$ at column $k$ adds $e$ to the \Col of the bit heap that lies in index k.
As previously mentioned, if the bit $e$ already exists in column $k$,
we propagate the bit to the next column, since $2^{k}c + 2^{k}c = 2^{k+1}c$.
Effectively, this implies that the bit heap is always in its canonical form,
where the weight of a bit is always equal to the weight of the column it is in.
This canonicalization also optimizes the bit heap during construction automatically,
by re-weighting bits that are added multiple times to the same column, and propagating them to the next column.
If a carry is propagated from the last column, 
it is dropped since we work with fixed-size bit heaps.
This is exactly what we want for reasoning modulo $2^w$.
Overall, this normalization design promotes both a simple API, a strong normal form,
and an optimized implementation of the bit heap data structure.
The correctness of insertion says that adding a bit to the bit heap at weight $k$ 
increases the total value of the bit heap by $2^k$ times the value of the bit expression (\autoref{thm:addBit}).

\begin{theorem}[Bit insertion]
\label{thm:addBit} 
For all bit heaps $h : \Heap_w$, bit expressions $c : \BitExpr$, weight $k : \mathbb{N}$,
and environment $\sigma : \mathcal{V} \to \mathbb{B}$,

  $\hsem{\mathtt{addBit}(k, c, h)}
   =
  \bigl(\hsem{h}
        + 2^{k}\cdot \csem{c} \bigr) \bmod 2^{w}.
  $
    \end{theorem}

The proof follows by functional induction on \texttt{addBit}, following the carry propagation described above.

\paragraph{Removal}
Removing a bit expression $e$ at column $k$ removes $e$ from the \Col of the bit heap that lies in index k.
Removal is only meaningful if the bit is present in the \Col; therefore, we require that the bit to be removed is present in the column.
This is encoded as an explicit hypothesis of the correctness theorem for bit removal, \autoref{thm:removeBit}.
Under this hypothesis, removing a bit $c$ from column $k$ decreases the value of the bit heap by $2^k \csem{c}$.
The proof does not require induction, since the removal of a bit only affects a single column.
Rewriting the corresponding bit-removal lemmas at the level of a single \Col proves this statement.

\begin{theorem}[Bit removal]
\label{thm:removeBit}
For all $h : \Heap_w$, $k : \mathbb{N}$, $c : \BitExpr$ and
$\sigma : \mathcal{V} \to \mathbb{B}$ with $c \in h_k$,
\[
  \hsem{\mathtt{removeBit}(k, c, h)}
  \;=\;
  \bigl(\hsem{h}
        - 2^{k}\cdot\lift{\csem{c}}\bigr) \bmod 2^{w}.
\]
\end{theorem}

So far, we have defined the bit heap data structure and its operations, and proved that they preserve the semantics of bit heap evaluation.
This gives us the foundational API to optimize bitvector arithmetic expressions,
which we will explain next.

\subsection{From Word-Level Arithmetic to Bit Heaps}
Our goal is to synthesize efficient and provably correct circuits for word-level arithmetic expressions.
We represent such arithmetic expressions as \Arith, a minimal symbolic
representation of word-level arithmetic. 
We will define a function $\mathsf{toBitHeap}$ that converts an \Arith expression into a bit heap.
This conversion then allows us to apply compression techniques that reduce the delay of the circuit (\autoref{sec:compression}).
First, we define the syntax and semantics of \Arith,
and then we prove that the semantics of the resulting bit heap are equal to the semantics of the original \Arith expression.

An \Arith is a word-level expression, which can be a variable,
a variadic addition of \Arith expressions,
or a multiplication of two \Arith expressions.
This allows us to represent nested arithmetic expressions, such as multiply-accumulate.
An \Arith variable $\mathsf{var}(i)$ represents the $i$-th input word.
We also support zero-extension of the variables, that allows us to fit narrow operands into a wider datapath,
as this is commonly needed in multiplication to preserve the full precision of the result 

\begin{align*}
  i \in \mathbb{N} \qquad v, w \in \mathbb{N}^{+}\\
  \mathtt{ArithCircuit}_w \ni a &::= \mathsf{var}(i)\\
  &\phantom{{}::={}} \mid \mathsf{zext}_{w}(a, e)\\
  &\phantom{{}::={}} \mid \mathsf{add}[a_0,\dots,a_{n-1}]\\
  &\phantom{{}::={}} \mid \mathsf{mul}[a, a]\\
\end{align*}

The \Arith variables are assigned a value by a variable environment $\rho : \mathbb{N} \to \mathtt{BitVec}\ w$, mapping each variable to a $w$-bit word,
where $\mathtt{BitVec}\ w$ is Lean's type of bitvectors of width $w$.
For a single variable, we evaluate it by truncating the value of the variable to its live bits, and zero-extending it to the width of the \Arith expression.
The addition and multiplication operations in \Arith are interpreted as the corresponding word-level operations.

\begin{align*}
  \bvsem{\mathsf{var}(i)} &= \rho\, i\\
  \bvsem{\mathsf{zext}_{w}(a')} &= \mathsf{zext}_{w}\big(\bvsem{a'}\big)\\
  \bvsem{\mathsf{add}[a_0,\dots,a_{n-1}]} &= \textstyle\sum_{t<n} \bvsem{a_t}\\
  \bvsem{a_0 \times a_1} &= \bvsem{a_0} \cdot \bvsem{a_1}
\end{align*}

\paragraph{Bit Heap Construction from Arithmetic Expressions}

In order to construct the bit heap from an \Arith expression, we work recursively.
Firstly, for an \Arith variable, we construct a bit heap with a single row, with one bit expression per live bit of the variable.

Secondly, the bit heap for addition is constructed by inserting the bits of each summand's heap into a single bit heap.
Intuitively, this is because the bit heap's value is a sum of the values of its bits.
Since insertion follows the propagation rule described above, adding a summand to itself promotes every bit to the next column,
resulting in a single-row bit heap where the summand is shifted up by one, i.e. $x+x = 2x$.
If instead the summands do not share any bits, the rows are stacked, 
resulting in a rectangular bit heap with height equal to the number of summands.

Finally, the bit heap for multiplication generates partial products of the two operands.
In our framework, we use the shift-add algorithm to build partial products.
This results in simple AND operations of the bits of the two operands, i.e.
$\big(\sum_{i} x_i 2^{i}\big)\cdot\big(\sum_{j} y_j 2^{j}\big) = \sum_{i}\sum_{j} (x_i \wedge y_j)\, 2^{i+j}$,
where each partial product $x_i \wedge y_j$ is inserted at column $i+j$ of the bit heap.

The correctness of these operations follow from the correctness of the bit heap operations.
The variable case follows directly, since the value of a word-level variable $x$ is equal to $\sum_i x_i 2^i$,
which clearly matches the value of the bit heap and proved trivially.
Similarly, taking the union of the columns of the bit heap preserves the value of the bit heap, 
using the identity $\sum_i h_i 2^i + \sum_j  h'_j 2^j = \sum_k (h_i + h'_i) 2^k$.
Similarly, partial products are proven equal using the identity $\sum_i x_i 2^i \cdot \sum_j y_j 2^j = \sum_{i,j} x_i y_j 2^{i+j}$.
Overall, this proves that the bit heap faithfully represents the value of the original \Arith expression (\autoref{thm:tobitheap}).

\begin{theorem}[Bit Heap Construction]\label{thm:tobitheap}
For all $a : \mathtt{ArithCircuit}_w$ and all $\rho : \mathbb{N} \to
\mathtt{BitVec}\ w$, writing $\sigma_\rho$ for the bit environment induced
by $\rho$,
\[
  \hsem{\mathsf{toBitHeap}(a)} \;=\; \bvsem{a}.
\]
\end{theorem}
 
Now that we have constructed a bit heap, we can build an optimized arithmetic circuit,
by using compression algorithms that efficiently express the same value as the original bit heap,
but with a much better circuit.

\subsection{Compression Algorithms For Fast Arithmetic}
\label{sec:compression}

To synthesize the bit heap into a fast arithmetic circuit,
the core idea is to repeatedly apply compressors (half and full adders),
which reduce the height of the bit heap.
When the bit heap is reduced to two rows, a single carry-propagate adder can be used to produce the final result.
This framework can be used to synthesize well-known, standard compression algorithms such as Wallace and Dadda trees \cite{dadda_tree,wallace_tree}.
In this section, we prove the correctness of compression algorithms, starting from a single compressor step.

Concretely, any compression algorithm produces a sequence of compression steps.
Formally, we define a \Step as either a half adder or a full adder, which takes the column index and the bits it consumes as arguments.

\[
\begin{array}{r@{\;}c@{\;}l@{\qquad}l}
\Step \ni s &::=& \HA(k,c,c) \mid \FA(k,c,c,c) &
\end{array}
\]

% The effects of a single step on the heap with the applicability conditions are shown in Table~\autoref{tab:steps}.
% Both applicability conditions are forced by Theorem~\autoref{thm:removeBit}, which requires bits to be present and that they are pairwise distinct.
Writing $h \xrightarrow{s} h'$ for the heap $h'$ obtained by applying step $s$ to $h$, we prove that each step preserves the value of the heap.

\begin{theorem}[Half/Full Adder Correctness]
\label{thm:step-correct}
For all $h : \Heap_w$, and $s : \Step$ if $s$ obeys the applicability conditions (\autoref{tab:steps}) and $h \xrightarrow{s} h'$, then $\hsem{h} \;=\; \hsem{h'}$.
\end{theorem}

This proof rewrites the goal using the lemmas for adding and removing bits (\autoref{thm:addBit}, \autoref{thm:removeBit}) until the
goal becomes an arithmetic identity over the Boolean values of bits.
This is then discharged by case analysis on the booleans, and some arithmetic reasoning.

Concretely, consider the half adder step $\HA(k,i,j)$, which removes $i$ and $j$ from column $k$,
and adds $i \oplus j$ at column $k$ and $i \wedge j$ at column $k{+}1$ (\autoref{tab:steps}).
Writing $h'$ for the resulting heap, the theorem states that the value of the heap is preserved:
\[
  \hsem{h'} \;=\; \hsem{h}.
\]
Unfolding $h'$ by rewriting the \texttt{addBit} and \texttt{removeBit} functions as well as the theorems (\autoref{thm:addBit}, \autoref{thm:removeBit}), 
we obtain an arithmetic expression:
\begin{equation*}
\begin{split}
  \bigl(\hsem{h}
    &- 2^{k}\csem{i}
     - 2^{k}\csem{j}\\
    &+ 2^{k}\csem{i \oplus j}
     + 2^{k+1}\csem{i \wedge j}\bigr) \bmod 2^{w}\\
  &\;=\; \hsem{h} \bmod 2^{w}.
\end{split}
\end{equation*}

The proof is discharged by case analysis on the four possible values of $i$ and $j$.
The full adder case follows the same pattern, with $\maj(i,j,l)$ instead of $i \wedge j$.

Having established that each individual step preserves the value of the heap, we now consider
sequences of steps.
Formally, a chain of compressors is an ordered list of compression steps, where each step is a half or full adder,
and is either empty or a step followed by a chain.

\[
\begin{array}{r@{\;}c@{\;}l@{\qquad}l}
\Chain \ni S &::=& [\,] \mid s :: S &
\end{array}
\]

We will notate this as $S \equiv s_0 :: s_1 \dots :: s_{n-1}$ for a chain of $n$ steps.
We write $h \xrightarrow{S} h'$ for the application of a chain $S$ to a bit heap $h$, producing a new bit heap $h'$.
This can be broken down into a sequence of applications $h = h_0 \xrightarrow{s_0} h_1 \xrightarrow{s_1} \dots \xrightarrow{s_{n-1}}  h'$.
We call a chain \emph{well formed}, iff, at each step $h_i \xrightarrow{s_i} h_{i+1}$, the applicability conditions of the step $s_{i}$
are satisfied by the intermediate bit heap $h_i$.
As above, the applicability conditions (\autoref{tab:steps}) ensure that the bits consumed by the step $s_i$ are present in the bit heap $h_i$,
and that the consumed bits are pairwise distinct.
This well-formedness condition allows us to prove the key chain correctness theorem (\autoref{thm:chain-correct}),
which states that any well-formed chain preserves the value of the bit heap.

\begin{theorem}[Chain Correctness]
\label{thm:chain-correct}
For all $h : \Heap_w$ and $S: \Chain$ is well-formed for $h$,
\[
  \forall \sigma,\quad
  \hsem{S(h)} \;=\; \hsem{h} .
\]
\end{theorem}

Chain correctness (\autoref{thm:chain-correct}) is proven by induction on the length of the chain.
The base case, when the chain has length $0$, is trivial, since the heap is unchanged.
For the induction step, the new step $s_{i+1}$'s correctness is justified by the step correctness theorem
proven above (\autoref{thm:step-correct}),
and the induction hypothesis is used to prove that the other steps preserve the value of the heap.

This therefore shows that \emph{any chain} of well-formed compression steps preserves the value of the bit heap.
We then use this to trivially prove the correctness of the Dadda algorithm.
It is easy to prove that the Dadda algorithm produces a well-formed chain of compression steps.
\osman{we need to explain why this is the case, and this part might be connected to the Integration section.}
However, see that our framework is general,
and can be used to prove the correctness of any compression algorithm that produces a well-formed chain of compression steps.

\begin{theorem}[Bit Heap Compression]
\label{thm:tobitheap-compression}
For all $a : \mathtt{ArithCircuit}_w$, all $\rho : \mathbb{N} \to
\mathtt{BitVec}\ w$, and $S: \Chain$ is well-formed for $h$,
\[
  \forall \sigma,\quad
  \hsem{S(\mathsf{toBitHeap}(a))} \;=\; \bvsem{a}.
\]
\end{theorem}

Finally, we prove that compression of word-level arithmetic expressions preserves the value (\autoref{thm:tobitheap-compression}).
The proof is a corollary of \autoref{thm:tobitheap} and \autoref{thm:chain-correct}.

\section{Related Work}
\citet{sca} presents a method based \ac{sca} approach to verify multiplication circuits, 
using backwards rewriting of polynomials at the gate level, employing a dynamic strategy consisting of sub-circuit detection and phase signal adjusting.
However, their verification tool itself remains to be unverified.

In their work, \citet{mertcan_acl2multipliers} prove correctness of integer multiplication circuits using a rewrite-based method in ACL2. 
Their approach can verify different partial-product generation and compression tree algorithms scaling to $1024\times1024$ bit multipliers in minutes. 
Similar to our approach, their implementation of the tool in a theorem prover guarantees the correctness of the verification tool.

A line of research focuses on proving \ac{hls} tools correctt. 
\citet{graphiti} introduces Graphiti, a graph-rewriting framework in Lean 4 to formally reason about optimizations on dataflow circuits.
Integrated into an existing HLS tool, Graphiti provides a verified rewriting engine that ensures the composition of verified rewrites refines the original behaviour.
